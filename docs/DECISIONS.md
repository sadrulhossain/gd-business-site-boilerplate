# Decisions

Log of architecture decisions. Format: `## NNN — Title` / Date / Decision / Why.

## 001 — phpredis, not Predis (superseded by 010)
2026-11-12. Use the phpredis extension (PECL redis 6.3.0). It compiles on PHP 8.5.12-fpm-alpine and loads; ACL user auth works through Laravel's `REDIS_USERNAME`/`REDIS_PASSWORD`. Predis is not installed.

## 002 — JSON error format
2026-11-12. Every exception renders as `{"error": {"code", "message", "details"?}}` via `App\Exceptions\JsonErrorRenderer`; `shouldRenderJsonWhen` is always true (API-only app). 5xx messages are hidden unless `APP_DEBUG`.

## 003 — API-only Laravel
2026-11-12. Skeleton web route, `/up`, welcome view, npm/Vite files and the skeleton's own CLAUDE.md/AGENTS.md were removed. Routes live in `routes/api.php` under `/api/v1`. Scramble serves docs at `/docs/api` (local env only).

## 004 — Tests use the compose services
2026-11-12. Pest runs inside the php container against the real Postgres/Redis from the container env (phpunit.xml forces cache/session to array, queue to sync). Health tests therefore need the stack up.

## 005 — Login flow: Authorization Code + PKCE (Passport 13)
2026-11-12. The admin SPA signs in with OAuth2 Authorization Code + PKCE (S256), no client secret.
- Client: public, fixed id `OAUTH_ADMIN_CLIENT_ID`, seeded by `OauthClientSeeder`; redirect `OAUTH_ADMIN_REDIRECT_URI`.
- First-party client skips consent (`App\Models\OAuthClient::skipsAuthorization`). Password grant stays off.
- Flow: SPA -> `api.*/oauth/authorize` -> API login page (session guard `web`) -> redirect with code
  -> SPA POST `/oauth/token` (code + verifier) -> access token (1h) + refresh token (30d)
  -> `Authorization: Bearer` on `/api/v1/*` (guard `api`).
- Built in phase 8 (see 011): the API login page for `/oauth/authorize` (session guard `web`, `GET/POST /login`).
- Keys: `storage/oauth-*.key`, generated by `fpm-start.sh`, git-ignored.

## 006 — Authorization model
2026-11-12. Spatie roles/permissions live on guard `api` (`User::$guard_name`, default guard `api`). Routes use
`->middleware('can:<permission>')`; `Gate::before` lets role `superadmin` through. Menus: `menus` table with an added
`title` column; a group row (no permission) shows only with a visible child. Tests refresh `<POSTGRES_DB>_testing`, never the dev DB.

## 007 — Content modules: edit-only, files on a volume
2026-11-12. Settings (one row, DB check `id = 1`) and Sections (seeded, immutable `key`) have no create/delete;
the portal renders by section key. Bilingual text uses `x` + `x_2nd` (`locales.second` = first supported locale
that is not the default). Uploads: disk root `UPLOADS_CONTAINER_PATH` (named volume `uploads-data`, shared by
php, php-queue, nginx), path `<dir>/<random>/original.<ext>`, extension from detected mime, WebP variants by a
queued job (GD). php-queue and php-scheduler run as `www-data` so files stay writable. nginx serves `/uploads/` static-only.
Tests: phpunit.xml `<env>` does not beat compose env, so `tests/bootstrap.php` forces the test environment.

## 008 - phpseclib 4.0.3 overrides Passport's 4.0.1 pin
2026-11-12. `laravel/passport` 13.11.0 (latest 13.x) requires `phpseclib/phpseclib` exactly 4.0.1, which has advisory
PKSA-h7cz-q7zq-mdkt (CPU-exhaustion DoS when parsing encrypted keys/PFX/CMS; fixed in 4.0.3). `api/composer.json` requires
`"phpseclib/phpseclib": "4.0.3 as 4.0.1"` (inline alias) so Passport's constraint is satisfied. Full test suite passes, `composer audit` clean.
Revisit when Passport releases a version that allows phpseclib >=4.0.3; then drop the alias and require plain `4.0.3`.

## 009 - Frontend: one pnpm workspace, source-only packages
2026-11-12. Root package.json + pnpm-workspace.yaml (`web/*`, `packages/*`) with a single `pnpm-lock.yaml`; shared versions live in the
workspace `catalog:` so react/react-dom/tailwindcss/typescript resolve once. pnpm runs via corepack (`packageManager`). Packages export
TypeScript/CSS source (no build step): Next and Vite compile them. `@gd/tokens` is Tailwind 4 `@theme` CSS, one file per app
(`admin.css`, `portal.css`, both on `base.css`); each theme resets `--color-*` so only its own palette exists. `@gd/api-types` is
generated from `packages/api-types/openapi.json` (`pnpm generate:types`, committed output). `@gd/api-client` is a dependency-free typed
fetch: Scramble documents updates as PUT while the API takes PATCH, so `patch` reuses the `put` types. Re-export the spec with `make
openapi` after migrating the dev DB (Scramble reads column types from it; without migrations every field degrades to `string`).
The node container mounts the repo at /app with named volumes over every node_modules; `make web` installs, regenerates types,
typechecks and builds both apps with NODE_ENV=production (Next prerender breaks under NODE_ENV=development).
## 010 - MariaDB, no Redis
2026-11-12. PostgreSQL is replaced by MariaDB 11.8.9 (LTS) using Laravel's `mariadb` driver and the `pdo_mysql` extension. Redis and phpredis are
removed: cache, sessions and queue use the `database` drivers (tables from the stock cache/jobs/sessions migrations). Consequences: queue
latency is polling-based (`queue:work --sleep=3`), cache locks and the rate limiter live in the `cache`/`cache_locks` tables, and the health
check reports `database` and `cache` (the `redis` key is gone). The test database is `<MARIADB_DATABASE>_testing`, created by
`scripts/ensure-test-db.sh`. Revisit if queue throughput or cache load outgrows the database; Valkey/Redis can come back behind the same Laravel drivers.

## 011 - Admin SPA: same-origin proxy, silent SSO, memory-only tokens
2026-11-13. The admin origin (nginx) proxies `/api/*` and `/oauth/token` to the API, so the SPA is same-origin with both and needs no CORS;
only the browser pages (`/oauth/authorize`, `/login`, `/logout`) live on the `api.*` origin. Passport's guard is `web` (a session login page,
`LoginController`, `throttle:login`); authorize with a non-first-party client is refused (403). Tokens live only in the Zustand store (never
local/sessionStorage; only the PKCE verifier and state cross the redirect, in sessionStorage). A reload therefore starts anonymous and the
route guard re-runs the authorize redirect, which the API's session cookie completes without a prompt (silent SSO). Refresh is single-flight
(`refreshTokens`), and the api-client retries a 401 once via `onUnauthorized`; a refused refresh clears the session, which sends the guard back to sign-in.
Sign-out: `POST /v1/logout` revokes the access and refresh tokens, then the browser goes to `GET /logout` on the API (ends the session) and
returns to `/signed-out`. Modules are config (`web/admin/src/modules.ts` -> `CrudPage`). Gaps: the sidebar has no icons; menu rows whose screen is
not built yet (posts, messages, settings) land on the 404 page. Browser tests run in the `e2e` compose service (official Playwright image,
profile `e2e`), not in the node container: Alpine's Chromium would not install reliably here.
